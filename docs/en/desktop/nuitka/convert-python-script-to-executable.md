# Convert a Python Script to an Executable

> **Note:** This document was generated by Claude Code and has not been reviewed by a human. Please use it as a reference only.

A guide to packaging `.py` files into a standalone Windows `.exe` using Nuitka — with steps to eliminate antivirus false positives.

> **Note:** PyInstaller is popular, but executables it produces are frequently flagged as malware by antivirus engines on VirusTotal. Nuitka compiles Python directly and, with the right configuration, produces clean binaries.

## Prerequisites

- Python 3.9 (via Conda recommended)
- [Visual Studio Build Tools](https://visualstudio.microsoft.com/visual-cpp-build-tools/) with the **MSVC v14.2** component installed
- Conda or pip for environment management
- *(Optional)* `osslsigncode` for digital signing

## Set Up a Clean Virtual Environment

Nuitka compiles everything in your Python environment into the binary. A bloated environment means a bloated `.exe`. Start fresh.

```bash
conda create -n nuitka python=3.9
conda activate nuitka
```

Then install only the packages your script actually needs:

```bash
pip install <your-dependencies>
```

> **Note:** Run your script in this minimal environment first to confirm it works before compiling.

## Install Nuitka

```bash
pip install nuitka
```

> **Note:** If false positives become an issue after a Nuitka version becomes widely adopted, try pinning to a slightly older version:
> ```bash
> pip install nuitka==<older-version>
> ```

## Build the Executable

Run the following command from your project directory, replacing `your_script.py` with your script name:

```bash
python -m nuitka \
  --msvc=14.2 \
  --lto=no \
  --standalone \
  --onefile \
  --onefile-tempdir-spec=my_app_tempdir \
  --plugin-enable=pylint-warnings \
  --plugin-enable=tk-inter \
  --windows-disable-console \
  --windows-product-name="MyApp" \
  --windows-file-description="My Application" \
  --windows-product-version=1.0.0.0 \
  --windows-company-name="YourCompany" \
  --windows-icon-from-ico=C:\path\to\icon.ico \
  your_script.py
```

## Understand the Build Flags

| Flag | Purpose |
|---|---|
| `--msvc=14.2` | Use the MSVC compiler. Less common than MinGW64, which reduces false positive rates. Alternatives: `--clang`, `--mingw`. |
| `--lto=no` | Disables Link Time Optimization. Speeds up the build. |
| `--standalone` | Bundles all dependencies into a `dist/` folder. |
| `--onefile` | Compresses the `dist/` folder into a single `.exe`. |
| `--onefile-tempdir-spec=<name>` | Sets where the `.exe` extracts itself at runtime. Without this, it extracts to `%TEMP%`. The folder is deleted automatically on exit. |
| `--plugin-enable=tk-inter` | Required if your script uses `tkinter`. |
| `--windows-disable-console` | Suppresses the console window at runtime. Note: `print()` statements will cause issues — comment them out before building. |
| `--windows-product-name` | Sets the product name in the executable's metadata. |
| `--windows-file-description` | Sets the file description in metadata. |
| `--windows-product-version` | Sets the version string (format: `0.0.0.0`). |
| `--windows-company-name` | Sets the company name in metadata. |
| `--windows-icon-from-ico` | Assigns a custom icon to the executable. |

> **Note:** MSVC and Clang require installation via **Visual Studio Installer → Modify → Individual Components**. If you still get false positives, try recompiling with each of the four compilers (`msvc`, `clang`, `mingw64`, `mingw`) to find the cleanest result.

## Reduce False Positives

Even a well-built Nuitka binary can trigger antivirus warnings. Check your result on [VirusTotal](https://www.virustotal.com) and use the following strategies if needed.

### Strategy 1 — Fill in Executable Metadata

Antivirus engines treat anonymous binaries with more suspicion. Always set:

```
--windows-product-name
--windows-file-description
--windows-product-version
--windows-company-name
```

### Strategy 2 — Switch Compilers

Recompile using a different compiler. Each one produces a slightly different binary signature:

```
--msvc=14.2
--clang
--mingw64
--mingw
```

### Strategy 3 — Use an Older Nuitka Version

As a Nuitka version becomes more commonly used (including by malware authors), detection rates rise. Pinning to an older version can help:

```bash
pip install nuitka==1.x.x
```

## Sign the Executable

Digital signing is the most effective solution. In testing, signing reduced a VirusTotal result from 13 detections to 0.

### Tools Needed

- A certificate (`.crt` / `.key`), either self-signed or from a CA
- [`osslsigncode`](https://github.com/mtrojnar/osslsigncode) — an open-source cross-platform signing tool

### Sign the Executable

```bash
osslsigncode sign \
  -certs your_cert.crt \
  -key your_key.key \
  -in your_app.exe \
  -out your_app_signed.exe
```

> **Note:** You can also use `signtool.exe` (from the Windows SDK) with a `.pfx` certificate as an alternative.

## Known Limitations

| Issue | Detail |
|---|---|
| **Japanese (multibyte) folder names** | Signed onefile `.exe` files fail to extract if there are Japanese or other multibyte characters in the folder path. Unsigned executables are unaffected. |
| **Workaround for path issue** | Use the unsigned `dist/` folder directly instead of the onefile `.exe`, or ensure the extraction path contains only ASCII characters. |
| `print()` with `--windows-disable-console` | Console output has no target, which can cause crashes. Comment out all `print()` calls before building. |
| **Persistent false positives** | Occasionally one detection may remain even after signing. No known complete fix; rotating compilers and Nuitka versions is the best mitigation. |
