# Fixing Greyed-Out Cowork Tab on Windows 11

> **Note:** This document was generated by Claude Code and has not been reviewed by a human. Please use it as a reference only.

Use this reference if Claude Desktop shows a **Chat / Cowork** slider, but you can't select "Cowork" — it stays greyed out.

## Background

Cowork runs inside an isolated Hyper-V-based VM. This requires:

- **Windows 11 Pro, Enterprise, or Education.** Windows 11 Home doesn't support Hyper-V (it's missing the `vmms` service), so Cowork can never be enabled on Home edition.
- **Hyper-V enabled** at the OS level.
- A specific driver (`vfpext.sys`) actually deployed on disk. This can silently fail even when Hyper-V reports as "Enabled."
- **Hardware virtualization enabled in BIOS/UEFI** (Intel VT-x / AMD-V / SVM Mode).
- A **paid Claude plan** (Pro, Max, Team, or Enterprise).

## Step 1: Upgrade Windows Home to Pro

If you're on Windows 11 Home, upgrade first through the Microsoft Store ("Upgrade to Windows 10/11 Pro"). This is a license upgrade, not a reinstall — your files and apps stay intact.

## Step 2: Check Whether Hyper-V's Core Service Exists

Open **PowerShell as Administrator** and run:

```powershell
Get-Service vmms
```

If you see `Cannot find any service with service name 'vmms'`, Hyper-V isn't installed yet.

## Step 3: Enable Hyper-V

```powershell
Enable-WindowsOptionalFeature -Online -FeatureName Microsoft-Hyper-V -All
```

This takes a few minutes and prompts a restart. Save your work and reboot when it's done.

## Step 4: Confirm Hyper-V Is Running After Reboot

```powershell
Get-Service vmms
```

The status should now show `Running`.

Fully quit Claude Desktop (tray icon → **Quit**, not just closing the window) and relaunch it. If Cowork is still greyed out — common if Claude Desktop was installed before Hyper-V existed on the machine — uninstall and reinstall Claude Desktop from [claude.com/download](https://claude.com/download), accepting the Windows UAC prompt during install. This registers the Cowork virtualization service machine-wide.

## Step 5: Resolve a "Missing HCS Services: vfpext" Error

If hovering over the disabled Cowork tab shows **"Missing HCS services: vfpext,"** this is a known Windows/Hyper-V driver deployment bug — the `vfpext.sys` driver (used for Hyper-V's virtual networking) fails to get copied to disk, even though Hyper-V reports as enabled.

Check the virtualization firmware status:

```powershell
Get-ComputerInfo -Property "HyperV*"
```

Confirm `HyperVisorPresent : True` and that virtualization firmware is enabled in BIOS.

Then confirm the driver file is actually missing:

```powershell
Test-Path C:\Windows\System32\drivers\vfpext.sys
```

If this returns `False`, the driver genuinely wasn't deployed — this matches the bug pattern.

## Step 6: Fix the Missing Driver

Run these in order, rebooting and re-checking `vfpext.sys` after each stage:

1. Enable related virtualization features:
   ```powershell
   Enable-WindowsOptionalFeature -Online -FeatureName Containers -All
   Enable-WindowsOptionalFeature -Online -FeatureName VirtualMachinePlatform -All
   ```
   Restart the PC.
2. If still missing, run a DISM repair (can take 10–20 minutes):
   ```powershell
   DISM /Online /Cleanup-Image /ScanHealth
   DISM /Online /Cleanup-Image /RestoreHealth
   ```
   Restart and re-check.
3. If still missing, run a system file check:
   ```powershell
   sfc /scannow
   ```
4. Also worth trying: clear Claude Desktop's cache through **Help → Troubleshoot → Restart**. In some cases the underlying components were actually fine, but Claude's own detection was stale.

## Step 7: Verify the Fix

```powershell
Test-Path C:\Windows\System32\drivers\vfpext.sys
```

This should now return `True`.

Fully quit and reopen Claude Desktop. The Cowork tab should now be selectable, with "Project or folder" and model options appearing underneath.

## Quick Checklist

- Windows 11 Pro, Enterprise, or Education (not Home)
- Paid Claude plan (Pro, Max, Team, or Enterprise)
- Latest Claude Desktop version
- `Get-Service vmms` returns `Running`
- Hardware virtualization enabled in BIOS
- `Test-Path C:\Windows\System32\drivers\vfpext.sys` returns `True`
- Claude Desktop fully quit and relaunched (or reinstalled) after each change

## Useful Commands Reference

```powershell
# Check Hyper-V core service
Get-Service vmms

# Enable Hyper-V
Enable-WindowsOptionalFeature -Online -FeatureName Microsoft-Hyper-V -All

# Enable related features
Enable-WindowsOptionalFeature -Online -FeatureName Containers -All
Enable-WindowsOptionalFeature -Online -FeatureName VirtualMachinePlatform -All

# Check virtualization/firmware status
Get-ComputerInfo -Property "HyperV*"

# Check the vfpext driver file
Test-Path C:\Windows\System32\drivers\vfpext.sys

# Repair Windows servicing components
DISM /Online /Cleanup-Image /ScanHealth
DISM /Online /Cleanup-Image /RestoreHealth
sfc /scannow
```

Report it through the thumbs-down feedback button in Claude Desktop, referencing "Missing HCS services: vfpext."
