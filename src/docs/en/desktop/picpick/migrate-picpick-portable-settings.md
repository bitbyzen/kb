# Migrating PicPick Portable Settings to a New Version

> **Note:** This document was generated by Claude Code and has not been reviewed by a human. Please use it as a reference only.

PicPick Portable doesn't use the Windows registry. Every setting — capture options, hotkeys, auto-save folder, JPEG/WebP quality, screen recorder options, editor behavior — lives in a single plain-text file called `picpick.ini`, sitting right next to `picpick.exe` in the portable folder.

Because both the old and new versions read that same file at startup, you can usually skip re-entering all your settings by hand: just close the old version, copy its `picpick.ini` into the new version's folder, and launch the new one.

## When This Works Well

- You're upgrading between two **portable** builds (not the installed/MSI version, which stores settings in the registry instead).
- The version jump is small (e.g. a patch/point release like 7.6.0 → 7.6.1). The ini format is very likely unchanged.
- You're not relying on anything version-specific that got redesigned (see [Caveats](#caveats) below — e.g. Screen Recorder settings moved out of the main Options dialog into their own panel in some versions, but they're still stored in the same ini file under a `[ScreenRecorder]` section).

## Step 1: Locate the Old Version's ini File

It's in the same folder as the old `picpick.exe` — for example:

```
\\<YOUR-NAS>\<YOUR-FOLDER>\picpick-portable\picpick.ini
```

or wherever your old portable copy lives. If you don't see it, the old version may never have had a setting changed/saved yet — the ini is only written the first time you open Program Options and click OK (or change something the app auto-saves, like window position).

## Step 2: Completely Close the Old PicPick

This step matters: PicPick keeps its current settings in memory and writes them back to `picpick.ini` on exit. If you copy the file while it's still running, your copy can get overwritten with stale data.

- Right-click the PicPick icon in the system tray (under the `^` hidden icons arrow if needed) and choose **Exit**.
- Double-check it's gone: open **Task Manager** (`Ctrl+Shift+Esc`) and confirm there's no `picpick.exe` process left under **Apps** or **Background processes**.

## Step 3: Back Up the New Version's ini (Optional)

The new portable folder will already have generated its own default `picpick.ini` the first time you ran it. Rename it just in case you want to compare later:

```
picpick.ini  →  picpick.ini.default.bak
```

## Step 4: Copy the Old ini into the New Folder

Copy `picpick.ini` from the old portable folder into the new one, replacing (or renaming over) the default file:

```
<new-picpick-portable-folder>\picpick.ini
```

## Step 5: Launch the New Version

Double-click the new `picpick.exe`. It should start with your old settings already in place — auto-save folder, hotkeys, capture options, recording settings, and so on.

## Step 6: Verify

Open **Options** (hamburger menu → **Options**, or the gear icon in Screen Recorder for recording-specific settings) and click through each tab to confirm things landed correctly:

- **General** — startup behavior, language, color theme
- **Editor** — hide-before-capture, background color, etc.
- **Capture** — multi-monitor, sound, magnifier
- **File Name** / **Auto Save** — naming pattern and save folder
- **Images** — JPEG/WebP quality
- **Hotkeys** — all your custom key combos
- **Screen Recorder settings** (gear icon in the recorder toolbar) — output folder, FPS, quality, audio

> **Note:** If Windows complains that a hotkey "cannot be registered" when you save (this can happen even with a legitimately-copied ini, if another app is temporarily holding that key combo), choose **No** when asked whether to change it — that keeps your intended combo in the file rather than resetting it.

## Caveats

- **Different major versions:** if you're jumping across a bigger version gap, new settings keys may have been added or renamed. Copying the ini should still work — PicPick will just fall back to defaults for any keys it doesn't recognize — but it's worth doing the verification pass in Step 6 rather than assuming a perfect match.
- **Window position / recent files:** the ini also stores things like the editor window's last position and size (`[Placement]`) and per-toolbar layout (`[QATBar...]`). These will carry over too, which is usually desirable but worth knowing.
- **No ini file yet:** if the old version never had its Program Options dialog opened/saved, there may be no meaningful `picpick.ini` to copy — in that case it's just using PicPick's defaults already, and there's nothing to migrate.
